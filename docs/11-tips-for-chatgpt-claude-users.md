# 11 · 给 ChatGPT / Claude 老用户的迁移指南

[← 返回目录](../README.md)

你已经很会和 AI 聊天了。Grok Bot 的难点不在「怎么写提示词」，而在 **思维方式的转变**：从「问一个聪明的聊天框」变成「给一个有电脑的同事派活」。

> 说明：本章对 ChatGPT / Claude 的描述仅作通用类比，不代表对其当前功能的完整或准确介绍；Grok Bot 部分均有官方依据。

## 1. 五个最大的不同

### ① 它有一台一直开着的电脑

聊天类 AI 的回答通常停在对话窗口里；Grok Bot 在 **自己的云电脑** 上、在 **你登录过的账号** 里把事情做完——发到日历、更新 Notion、填好购物车、开出 PR。官方的说法是"工作落在真正的工具里，而不是一份需要你再搬运的草稿"。

而且这台电脑是 **持久的**：文件、浏览器登录、偏好一直都在；**你合上笔记本，它还在干活**。

### ② 你管理的是「一组同事」，不是「一堆对话」

| 你习惯的 | Grok Bot 里的对应 |
|---------|-----------------|
| 每个话题开一个新对话 | 每类 **工作** 一个 Bot，长期使用同一个 Bot |
| 项目/自定义助手里写一段系统提示 | 第一条消息告诉 Bot 岗位与规则，并说"请记住" |
| 全局记忆 | **每个 Bot 各自的记忆**（互不混杂） |
| 复制粘贴上下文到另一个对话 | Bot 之间直接 **交接**，或放进 **群聊** 协作 |
| 自定义助手分享 | 分享 **Bot 模板**，或团队共用 **Team Bot** |
| 定时任务 | **例程**：不仅能定时，还能被 Slack、GitHub、邮件、Webhook 等事件触发 |
| 文档/画布类输出 | **Pages**：可持续更新、可分享的报告和看板 |
| 选择模型 | **没有模型选择器**，Grok Bot 为每个任务自动选 |

### ③ 主动做事 + 主动停下

它会一路做下去，**只在需要你判断或批准时回来找你**：登录、验证码、付款、发邮件、删除。你的工作从「一步步指挥」变成「设边界 + 批审批 + 验收结果」。

### ④ 能力随连接和登录增长

它能做什么，很大程度取决于你给了它什么：连了哪些应用、在云电脑上登录了哪些网站、保存了哪些技能。第一天别急着全连上，**按需添加**。

### ⑤ 用量按「工作量」算

用量消耗看的是 Bot 做了多少步、处理了多少内容，而不是你发了几条消息。一个大任务可能比几十条闲聊还耗。例程、群聊里每个 Bot 的回复、Bot 之间的消息都算用量。

## 2. 思维转换：从「问」到「派活」

**❌ 聊天思维**

```text
帮我写一封跟进邮件给客户。
```

**✅ 派活思维**

```text
看一下我 Gmail 里和 Acme 公司最近的邮件往来，起草一封跟进邮件：确认上周提到的报价，问他们预计什么时候能签。
用我平时给客户写信的语气（先看几封我发给他们的邮件）。起草好给我看，不要发送。
```

好任务的五要素（综合官方「好的第一次交接」与用例页）：

1. **做什么**（目标）
2. **在哪做 / 用什么数据**（来源、工具）
3. **约束和边界**（不能碰什么、哪一步必须停）
4. **交付物长什么样**（文档 + 来源链接？表格 + 指定列？草稿？）
5. **完成标准**（什么时候算做完、失败了怎么办）

官方示例（中文意译）：

```text
从 CRM 拉出本周的 pipeline 复盘名单，跳过已经在跟进序列里的人。在网上和 Slack 里调研排名前五的客户，
找到合适的联系人，用我的语气起草外联邮件，明早之前留给我待审的草稿。
```

## 3. 需要改掉的老习惯

| 老习惯 | 在 Grok Bot 里改成 |
|-------|-----------------|
| 把密码、API Key 贴进聊天 | 用 Bot 弹出的安全表单/安全密钥卡片，或接管电脑自己输入 |
| 让 AI "告诉我怎么做"，然后自己去做 | 直接让 Bot 去做，你只处理登录和审批 |
| 把网页内容复制给 AI | 直接发链接；需要登录的页面让 Bot 去开，你登录一次 |
| 一个万能对话聊所有事 | 按岗位拆成多个 Bot |
| 每次重讲背景 | 让 Bot "记住"长期规则；把流程存成技能 |
| 让 AI 凭记忆回答关键数字 | 让 Bot 重新打开源数据并附上链接 |
| 自己定时回来问进展 | 打开 Bot 的通知；或用例程定时汇报 |
| 怕它乱来于是什么都不让做 | 用审批 + Auto-review 规则 + 请求里的边界来控制风险 |

## 4. 第一周建议路线

**第 1 天**：用默认的 Grok Bot 做 2–3 个只读任务（总结文档、调研一个主题、整理一份清单）。设置中文界面、时区、Auto-review 规则。

**第 2 天**：连接 1–2 个最常用的应用（例如 Gmail + Google 日历）。试试"今天我需要处理什么"。

**第 3 天**：建第二个有明确岗位的 Bot（例如「收件箱管家」或「出行助理」），写好岗位说明并让它记住。

**第 4 天**：把一个跑通的流程存成 **技能**，再做成第一个 **例程**（例如工作日早报），用 **Test** 测一下。

**第 5 天**：试一次需要登录网站的任务，体验「接管」和安全表单。

**第 6–7 天**：试试群聊协作，或让 Bot 做一个 Page；回顾哪些例程有用、哪些是噪音，调整频率。

## 5. 中文用户小贴士

- 界面语言：**Settings → General → Language → Chinese (Simplified)**（桌面支持 36 种语言，手机 12 种，均含简体中文）。新 Bot 会用界面语言和你交流，除非你用其他语言跟它说话。
- 语音通话的语言在通话中的 **Show settings → Language** 里单独设置（可选 Auto-detect）。
- 你可以中英混用：例如用中文下指令，要求"邮件用英文写"。可以让 Bot 记住"给我的回复用中文，对外邮件按收件人语言"。
- 时区：例程按 **Settings → General → Bot → Timezone** 计算；人在国外或经常出差时记得检查。

## 6. 实用提示词模板（复制即用）

### 给新 Bot 定岗位

```text
你叫「<名字>」，你的工作是 <一句话岗位>。
信息来源：<应用/网站/文件夹>。
输出格式：<例如：先给结论，再列证据，每条附链接>。
必须先问我的事：<例如：发任何消息、购买、删除、改日历>。
绝不做的事：<例如：联系客户、改生产设置>。
请记住以上内容，用于以后所有工作。
```

### 要可审阅的结果

```text
完成后请分开列出：① 从源系统查到的事实（附链接）② 你的假设 ③ 已经完成的操作 ④ 等我批准的操作 ⑤ 没能核实的问题。
```

### 把一次性任务固化

```text
刚才这个流程很好。请把它保存成技能「<名字>」，写清楚何时使用、需要哪些输入和权限、步骤、怎么验证结果、返回什么、哪些步骤要我批准。
然后设一个例程：每个工作日早上 9 点用这个技能跑一次，结果发到这个对话；没有新内容就不用发。
```

### 纠正记忆

```text
你记得的「我的常用机场是成田」已经过时了，现在改成羽田。请更新记忆。
```

### 让它停

```text
Stop now.
```

（立即停止当前工作；已经完成的操作不会被撤销。）

## 7. 社区经验（未经官方验证，仅供参考）

- 「长对话更耗用量」：有用户认为 Bot 每次回复都会重读整个对话历史，建议把稳定的知识存成技能/记忆后开新对话（X 用户 @XStrangeHistory）。**官方未就此给出说明**；官方明确的是：用量取决于 Bot 的步骤和处理量。
- 「每个例程给一个便宜的第一步」：先检查有没有新东西，没有就结束（X 用户 @MikeysMolecules）。
- 「一个 Chief of Staff Bot 统筹其他专家 Bot」：官方博客和多位用户都在用这种模式。
- 「例程可能会延迟 10–20 分钟触发」（Reddit r/GrokBot 用户反馈）。
