# 04 · 例程（Routines）：让 Bot 在你不在时自动工作

[← 返回目录](../README.md)

## 1. 例程是什么

**例程 = 一个保存好的指令（Instruction）+ 一个触发条件（When to run）**，归属于某一个 Bot。

- 可以 **定时** 运行（每天、每个工作日、每两小时……）；
- 也可以在 **事件发生时** 运行：Slack 消息、GitHub / Linear / Sentry / PagerDuty / Microsoft Teams 事件、发到 Bot 邮箱的邮件、外部系统调用 Webhook；
- 在云端运行，**你合上电脑也照跑**。

官方推荐的成熟路径：**先手动完成一次 → 修正到满意 → 保存成技能 → 再做成例程。**

## 2. 怎么创建

**直接在聊天里告诉那个负责这件事的 Bot**：做什么 + 什么时候 + 结果发到哪里 + 边界 + 数据源缺失怎么办。

```text
每个工作日早上 8:00，用「每日客户风险」技能检查当前客户列表，在这个对话里发一份带链接的观察清单。
不要联系任何客户。如果数据源不可用，直接报告失败，不要用旧数据凑数。
```

Bot 创建前可能会弹出确认卡片（显示时间表和指令），你点确认后才会保存。手机上也可以在 Bot 资料页 **Routines → Add routine**，App 会帮你起个头 "Set up a routine to "。

创建前确认清单（官方）：

- [ ] 由哪个 Bot 负责
- [ ] 时间表和 **时区**
- [ ] 输入数据从哪里来
- [ ] 期望的结果长什么样、发到哪里
- [ ] 审批边界（哪些动作必须停下来问你）
- [ ] 数据源缺失时怎么办

## 3. 在哪里查看和管理

**桌面端**：点对话顶部 Bot 名字 → **Details** 标签 → **Routines**。

- 每行显示名称和运行时间（或 **Paused**），行上的开关可暂停/恢复。
- 点开某个例程：**Instruction**（每次做什么）、**When to run**（时间表和触发事件，用自然语言显示）、**Webhook**（如果是 Webhook 触发）。
- 底部按钮：**Pause / Resume**、**Test**、**Edit**、**Delete routine**（垃圾桶，需确认，**不可撤销**）。
- **Edit** 会在输入框里预填 "Edit your routine: <名称>"，你补上要改什么再发送。

**手机端**：Bot 资料页 → **Routines** → 查看 **Active**、**Schedule**、**Next run**、**Instruction**、**Run history**（Running / Succeeded / Failed，失败会显示原因）。关闭 **Active** 即暂停；左滑删除。

限制（官方文档）：每个 Bot 最多 50 个例程；每个例程保留最近 20 条运行记录；定时间隔至少 5 分钟。删除 Bot 会同时删除它的例程。长时间不使用时，Grok Bot 可能会问你是否继续运行例程，没回应就会暂停它们——回来后记得检查。

## 4. 时间与时区

- 时间表使用 **Settings → General → Bot → Timezone**（**Auto-detect** 跟随本机）。需要跟随某个办公室的时区时可以单独指定。
- 用自然语言说："每个工作日早上 8 点"、"每 2 小时"，然后打开例程检查 **When to run** 是否正确。
- **新例程不会立刻运行**，会等到下一个时间点。8:05 创建"每天 8:00"，第一次运行是明天 8:00。想马上试就用 **Test**。
- 关于具体分钟：如果你只说"8 点"而没说"8 点整"，Bot 可能把时间存在 8 点前后几分钟（避开整点高峰），并告诉你实际存的时间；要整点就说"8 点整"。
- 你说"每天检查一下"这种模糊表述时，Bot 默认会排在 **工作日的白天**（不在深夜、不在周末）；生活类提醒（吃药、宠物、习惯打卡）则会覆盖一周七天。想要周末也跑就明确说"包括周末"。
- 社区反馈（Reddit）：例程触发可能会有 10–20 分钟延迟，**对时间极敏感的事情不要完全依赖例程**。（社区经验，非官方数据）

## 5. 触发器类型一览

| 类型 | 典型用法 | 要点 |
|------|---------|------|
| 定时（Schedule） | 早报、周报、价格巡检、每周提醒 | 最短间隔 5 分钟；默认工作日白天 |
| Slack | 被 @ 时、出现关键词时、你自己加了某个表情时、某频道任何新消息时 | 可以盯一个频道或全部；**频道触发需要先在 Slack 里把 Cursor 应用邀请进那个频道**（在频道里输入 `/invite @Cursor`），私有频道不邀请连找都找不到；只算触发器创建之后的新消息 |
| GitHub | PR 新建/推送/合并/关闭、评审请求/通过/要求修改、评论、CI 通过/失败、Issue 被指派 | 一个例程对应一个具体仓库；可以只盯某个 PR；"盯这个 PR 直到合并"会在合并或关闭后 **自动删除** |
| Cursor Origin | 与 GitHub 类似的 PR / CI 事件 | 仅限原生 Origin 仓库 |
| Linear | 新建 Issue、状态变化、Cycle 结束 | 可按项目/团队过滤 |
| Sentry | Issue 新建/解决/指派/归档等 | 可按项目过滤 |
| PagerDuty | 事故触发/确认/解决/升级 | 可按服务过滤 |
| Microsoft Teams | 指定团队/频道的新消息，可按关键词 | 需要租户和团队信息 |
| Email | 有邮件发到你的 Grok Bot 邮箱时 | 可限定发件人或整个域名（`*@example.com`）；默认只对通过邮件认证（SPF/DKIM/DMARC）的发件人触发；**不能按主题过滤**；`名字+标签@` 形式的地址可以各自触发不同例程 |
| Webhook | 外部系统 POST 一个请求就触发 | 在例程面板复制 **POST to**（URL）、**key**、**header**（`Authorization: Bearer <key>`）；可带 JSON 正文；返回 **200** 只代表「已接受并开始运行」，不代表完成 |
| 组合 | 同一个指令既定时又按事件触发 | 例如"每天早上 9 点汇总，另外有人在 #incident 提到我时立刻处理" |

事件触发器走的是你 **Cursor 账号里的集成连接**（和 Cursor 云端代理自动化用的是同一套），而不是你粘贴给 Bot 的令牌。如果平台还没连接，保存例程时会自动弹出连接卡片。

> **优先用事件触发，不要用定时轮询去「盯」Slack 或 GitHub。** 定时轮询既慢又费用量。

## 6. 测试

- 打开例程点 **Test**，按钮显示 **Running…** 直到结束，结果出现在 Bot 的对话里。
- ⚠️ **测试会真的执行**：会浏览网站、改文件、调用连接器。用安全的输入，把写操作放在审批之后。
- 测试后检查：用的是不是最新输入？格式对不对？每个动作有没有来源/记录？有没有在预期的审批点停下？失败状态是否写明？
- 有些例程不显示 Test，但它们仍会按时间表/触发器运行。

## 7. 例程与审批、登录、付款

- 例程运行时遇到需要审批的动作，审批卡片 **大约 10 分钟后会过期**（因为不是你在场发起的）。所以：给跑例程的 Bot **打开通知**；对真正信任的动作用 **Always allow**。
- 例程 **不能自己填已保存的密码、银行卡等机密**——安全填写需要你在场。遇到这一步时它会在聊天里叫你。
- 例程要发的邮件 **永远停在草稿**，等你按 **Send**。没有无人值守发送的选项。
- 如果某个例程依赖的连接器授权失效且反复失败，Bot 可能会暂停这个例程并告诉你要重新连接什么。

## 8. 省用量

每次运行都消耗用量。一个每小时、短间隔，或盯着热闹频道「任何消息」的例程，可能一天就用掉一周的量。

- 暂停不需要的例程；
- 放宽时间表（每天 → 每个工作日；每小时 → 工作时间内每两小时）；
- 收窄 Slack 触发（指定频道 + 指定短语）；
- **给每个例程一个「便宜的第一步」**：先检查有没有新东西，没有就安静结束（社区技巧，X 用户 @MikeysMolecules）；
- "没有新内容时不要发消息"写进指令里；
- 有明确终点的盯梢（"盯到它降价为止"、"PR 合并后停"）要写清截止时间或结束条件，让例程 **自动删除**。

## 9. 实战示例（可直接复制修改）

### 每日早报

```text
每个工作日早上 8:30，给我一份早报：今天的日历安排、昨晚以来需要我处理的未读邮件（只挑需要我回复或决定的）、
以及我关注领域在 X 上的重要新闻。每条附链接。没有重要内容的板块直接省略。结果发在这个对话里。
```

### 周一「生活运营」复盘（改编自社区分享，X 用户 @mikepat711）

```text
每周一早上 9 点，只观察不行动：扫一遍我上周在 Grok Bot 里的工作——各个 Bot 的资料、近期记忆和例程。
找出：重复的手工劳动、应该有例程却没有的 Bot、断掉的交接、可以用连接器替代浏览器登录的地方、
值得变成每周任务的一次性工作。最多给我 1–3 条建议，每条都对应你看到的具体事情。没什么可说就保持安静。
不要给其他 Bot 发消息，不要改动任何账号或例程，先问我。
```

### 价格监控（会自动结束）

```text
帮我盯着这个商品：<商品链接>。价格低于 ¥1500 时告诉我。每天看一次就行，降到目标价或者到 12 月 31 日就停止并删除这个例程。
```

> Bot 的做法可能是：如果商店提供「降价/到货邮件提醒」，它会用你 Bot 邮箱的带标签地址（如 `名字+watch-kettle@...`）订阅提醒，并设置一个「收到这个地址的邮件时」触发的例程；收到提醒后再打开商品页核对是否真的低于你的目标价。商店不提供提醒，或者需要确认邮件，它就改为每天检查一次页面。

### GitHub PR 看护

```text
盯着 <owner/repo> 的 PR #123：有新评审、评论、CI 失败或通过时告诉我并总结要点；PR 合并或关闭后自动停止。
```

### Slack 关键词响应

```text
当 #customer-escalations 里有人发了带工单链接的消息并且包含 "needs repro" 时，打开工单，在 staging 环境复现问题，
把复现步骤、截图和环境信息发到这个对话。未经我批准不要在 Slack 里回帖。
```

### 用表情当信号

```text
当我在 Slack 任何频道给一条消息加上 :eyes: 表情时，把那条消息的上下文整理成一条待办，加到我的 Notion 待办数据库里。
```

### 邮件触发：账单处理

```text
当 billing@example.com 发来邮件时，读取内容，提取金额、到期日和账单编号，汇总告诉我。如果需要回复，起草好等我确认，不要自动发送。
```

### Webhook：外部系统交任务

```text
给这个 Bot 加一个 Webhook 触发的例程：收到请求时，读取 JSON 正文里的 task 字段并执行，完成后把结果发到这个对话。
任何会给别人发消息、付款、删除数据或泄露密钥的任务都拒绝并说明原因。
```

### 周日晚规划下周

```text
每周日晚上 8 点，帮我规划下周：看一下日历，标出冲突和没留缓冲的连续会议，建议 2–3 个专注时间块。只提建议，不要直接改日历。
```

更多示例见 [examples/prompts.md](../examples/prompts.md#例程-routines)。

## 10. 例程为什么没运行？

1. 例程是否被 **Paused**（手机上 **Active** 是否打开）？
2. **When to run** 是否是你期望的时间表/触发器和时区？
3. 新例程要等下一个时间点；想立刻跑用 **Test**。
4. Slack：是不是新消息？是否在被监听的频道？是否匹配短语？**Cursor 应用是否已被邀请进频道？**
5. Webhook：是否返回 200？是否用的是当前 key？
6. 出现 "Automation run rate limit exceeded"：已知问题（所有例程共享的限制），不会自动重试，用 **Test** 或重发 Webhook 手动补跑。
7. 没暂停但 24 小时以上没跑、也没报错：向官方报告 Bug，附 Bot 名和例程详情。
