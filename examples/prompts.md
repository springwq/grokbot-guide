## 给 Bot 定岗位

**通用模板**
```text
你叫「<名字>」，你的工作是 <岗位>。信息来源：<来源>。输出格式：<格式>。
必须先问我的事：<列表>。绝不做的事：<列表>。请记住这些规则，用于以后所有工作。
```

**研究员**
```text
一次只研究一个主题，使用网页和我分享的文档。总结主要发现并附来源链接，事实和推测分开写。改动任何外部服务前先问我。请记住。
```

**收件箱管家**
```text
你负责我的 Gmail 收件箱。每天帮我把需要我回复或决定的邮件挑出来，按紧急程度排序，每封一句话说明要我做什么。
可以起草回复，但任何邮件都不要发送，归档或删除前也要先问我。请记住。
```

**出行助理**
```text
你负责我的出行。我的常用机场是 <机场>，偏好 <航司/座位>，酒店预算一般每晚 <金额>。
查询可以随便做，任何预订、付款前必须给我看总价并等我确认。请记住。
```

**Chief of Staff（总管）**
```text
你是我的 Chief of Staff。你了解我的优先事项（见附件文档），负责协调我的其他 Bot：需要专业工作时交给对应的 Bot，
但每个阶段只安排一个负责人。只在需要我做判断时找我。不要代我对外发送任何消息。请记住。
```

**产品性能调查员**（官方示例改编）
```text
你的工作是产品性能。用我们的可观测性工具调查性能问题。保留链接和截图，区分证据和假设，最先说影响最大的问题。
绝不修改生产设置。请记住。
```

## 研究与信息整理

```text
调研 <主题>：找 5–8 个高质量来源，给我一份 1 页的摘要：核心结论、主要分歧、还没定论的问题。每个论点附链接。
```

```text
比较 <产品 A>、<产品 B>、<产品 C>：价格、核心功能、限制、适合谁。做成表格，每个单元格的信息注明来源。
```

```text
我在考虑 <决定>。帮我列出支持和反对的最强论据各 3 条，并告诉你认为我还缺什么信息。
```

```text
把这个链接里的长文总结成 5 个要点，再用一段话说明它和我上周让你研究的 <主题> 有什么关系。
```

```text
在 Slack、Notion 和 GitHub 里找一下我们团队关于 <话题> 的讨论和决定，按时间线整理，附原始链接。
```

```text
总结这份文档，5 个要点。另起一节列出所有日期、决定和未解决的问题，每条注明出处章节。不要修改原文件。
```


```text
把 <某人> 周五的分享会放到我日历上，只是提醒我自己，不要邀请任何人。
```

```text
明天 10 点那个会改到下午 3 点。先告诉我会上都有谁、改了会通知谁，等我确认。
```

```text
明天有 3 个外部会议。每个会前给我一份简报：对方是谁、我们之前的邮件往来要点、这次可能要讨论什么。
```

```text
这是会议录音的转写稿（附件）。整理成纪要：决定、待办（负责人-事项-截止日期，没说清楚就写"未指定"）、未决问题。
再起草一封跟进邮件给与会者，给我看，不要发。
```

```text
帮我在 <网站> 上预约下周六上午的 <牙医/理发/健身课>，订之前给我看时间和费用。订好后把确认号写进日历。
```

## Pages（报告与看板）

```text
做一个页面，对比这个邮件串里的三份报价：表格列出价格、交付时间、付款条件，最后给一段简短建议。
```

```text
做一个「我的 Bot 状态」看板：列出我所有的 Bot，各自的岗位、例程、最近一次运行结果。每个工作日早上更新一次。
```

```text
做一个下周出差的行程页面：按天列出交通、酒店、会议，附确认号和链接。之后有变化你就更新这个页面。
```

```text
做一个每日状态页：今天的日程、待回复的重要邮件、进行中的任务。每天早上 8:30 刷新。
```

```text
把这个页面的图表换成按周汇总，再加一个按渠道的筛选器。
```

## 例程 Routines

```text
每个工作日早上 8:30 给我早报：今天的日历、昨晚以来需要我处理的邮件、我关注领域在 X 上的重要新闻。每条附链接，没有内容的板块省略。
```

```text
每周一早上 9 点，帮我回顾上周：我完成了什么、有哪些事拖着没做、本周最重要的 3 件事建议。
```

```text
每周日晚上 8 点，看一下下周的日历，标出冲突和连续没有缓冲的会议，建议几个专注时间块。只提建议，不要改日历。
```

```text
帮我盯着这个商品：<链接>。低于 <价格> 时告诉我。每天看一次，降到目标价或到 <日期> 就停止并删除这个例程。
```

```text
盯着 <owner/repo> 的 PR #<号>：有评审意见、评论或 CI 结果时告诉我要点；合并或关闭后自动停止。
```

```text
当有人在 Slack 里 @ 我并且包含 "urgent" 时，马上把消息和上下文转给我，并建议一个回复（不要替我回）。
```

```text
当我在 Slack 任何消息上加 :pushpin: 表情时，把那条消息整理成待办加到我的 Notion 待办数据库。
```

```text
当 <发件人邮箱> 给你的邮箱发邮件时，读取并提取关键信息总结给我；需要回复的话起草好等我确认。
```

```text
给这个例程加一个 Webhook 触发：收到请求时读取 JSON 里的 task 字段并执行，结果发到这个对话。
```

```text
每个工作日早上 9 点运行 @<技能名>，然后把结果更新到 <页面名> 页面上。数据源不可用就报告失败，不要用旧数据。
```

```text
每天早上 8 点提醒我吃药，周末也要。
```

```text
我的例程用量好像太高了。帮我列出所有例程的频率，建议哪些可以放宽或合并，哪些可以暂停。先给方案，不要直接改。
```

```text
先检查 <数据源> 有没有新内容；没有就安静结束，不要发消息。有的话再做完整分析。（把这句加到我所有监控类例程的开头）
```


```text

```

```text
不要给其他 Bot 发消息，需要协作时先问我。请记住。
```

## 工作场景：销售、招聘、运营、财务

以下改编自官方用例页，**每条都刻意停在审阅点**。

**销售外联**
```text
调研这个 CRM 视图里的 25 个客户。按我们的理想客户画像和近期意向打分，每个客户找最多 3 个合适联系人，
参考附件的风格起草邮件和 LinkedIn 外联。跳过已在跟进序列中的人。返回待审列表，不要发送或加入序列。
```

**人才搜寻**
```text
根据这份职位描述，找 20 位满足必备条件的候选人。排除已在我们 ATS 里的人，说明每个人匹配的证据，用我的语气起草个性化外联。不要联系任何人。
```

**投放监控**
```text
拉取各广告系列当前的花费和表现，和月度预算及目标获客成本比较，给出带数据支撑的预算调整建议。为增长团队起草一条 Slack 更新。不要改预算，也不要发消息。
```

**报销管理**
```text
根据报销系统和附件政策生成本周报销汇总。匹配财务邮箱里的收据，标出缺失类别或违反政策的项目，每个负责人起草一封跟进。只返回汇总和草稿，不要发送，不要修改报销。
```

**客户健康度**
```text
复盘这个组合里的客户：综合近期使用量、客服升级、续约时间和关键联系人活跃度，生成排序后的观察清单。每个客户附证据、为什么重要和建议的下一步。不要联系客户或编辑 CRM。
```

**Bug 复现**
```text
阅读这个 Bug 报告，用一个全新的测试账号在 staging 复现。返回确切步骤、期望与实际行为、截图、浏览器和系统信息，可能的话给一个最小测试用例。不要使用生产环境的客户数据。
```

**Chief of Staff 日报**
```text
回顾我授权的频道、收件箱、日历和会议纪要自昨天以来的动态。只返回和这份文档中优先事项相关的条目。每条附来源、为什么重要、建议的下一步、我是否需要做决定。不要发消息，不要改会议。
```

## 求职
