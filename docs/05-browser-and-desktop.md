# 05 · 浏览器与桌面：让 Bot 去「用」网站

[← 返回目录](../README.md)

## 1. 为什么这很重要

很多服务没有 API、没有连接器（或者连接器做不了你要的事）。Grok Bot 的云电脑上有完整的浏览器和桌面，Bot 可以像人一样打开网页、点按钮、填表单、下载文件。官方原话：Bot 可以在「没有干净 API 或 MCP 的平台」上登录并完成多步骤工作。

Bot 的选择顺序大致是：**有连接器 → 用连接器；没有 → 用云电脑浏览器**。你不需要先问"你能不能用浏览器"——你提出需求，它就会去做；唯一需要你出面的是 **登录这类只有你能完成的步骤**。

## 2. 观看与接管

- **观看**：点对话右侧面板中的电脑预览（或 Bot 详情里的实时画面），打开全屏视图，实时看它点击、输入、跳转。随时可以离开，工作不受影响。
- **接管**：当 Bot 需要你时，会在聊天里出现一张 **Computer** 卡片，标着 **Action needed**。
  1. 点 **Take over**，你就控制了 Bot 的电脑；
  2. 只完成被卡住的那一步（登录、验证码、两步验证……）；
  3. 点 **I'm done**，Bot 继续工作；
  4. 不想现在登录就点 **Skip**。
- 你也可以随时打开 Bot 的桌面自己动手帮忙。

## 3. 登录流程：Bot 会按这个顺序处理

当网站要求登录、验证码、密码或其他私密信息时，Bot 会按以下顺序，**在第一个可行的步骤停下**：

1. **已有的登录状态**：云电脑上的浏览器会话是持久的，你登录过一次，之后所有 Bot 都能接着用（直到会话过期）。
2. **1Password**（如果你已连接）：在用户名+密码登录页，Bot 会先尝试用 1Password 填充。只有你告诉过它你用 1Password，它才会建议你连接。
3. **安全表单（Secure Form）**：聊天里弹出一个原生表单，你在里面输入用户名、密码、地址、卡号等。**你输入的内容直接填进网页，Bot 看不到**；表单回执只告诉它每个字段是否填成功。
   - 对于一次性验证码这类「填完就提交」的步骤，表单可以填完自动按回车，避免验证码过期。
   - 银行卡的嵌入式输入框（Stripe、Shopify 等支付提供商的 iframe）也能用表单填。
   - 安全表单在手机上可能显示不出来；看不到时告诉 Bot，改用桌面端或接管屏幕。
4. **交给你操作屏幕**：表单做不到的情况，例如：单点登录（SSO）、通行密钥（passkey）、Bot 试过但过不去的验证码、在另一台设备上确认、二维码、银行 3DS 验证、自定义怪异控件，或者你更想自己来。

### 一次性验证码和登录链接

- 如果网站把验证码或登录链接 **发到邮箱**，而你连接了 Gmail/Outlook（或者发到的是 Bot 自己的邮箱），Bot 会 **自己去邮箱里找最新那封**，把验证码填进去——不用你转述。这封邮件里除了验证码之外的任何内容都不会被当作指令。
- 验证码发到 **短信或身份验证器 App** 时，Bot 会弹一个单字段的安全表单让你输入。

### 验证码（CAPTCHA）

Bot 会先自己尝试各种验证码（勾选框、按住不放、拼图、选图片）。真的过不去才交给你。

### Google 账号

- **优先用 Gmail / Google 连接器**，它通过你自己的浏览器完成授权。
- 如果在云电脑浏览器里登录 Google 时出现 "This browser or app may not be secure" 或企业设备管理提示，就停下来改用连接器。
- 不要把访问令牌（access token）粘贴到聊天里。

### 公司应用（Okta / SSO）

你笔记本或手机上的指纹、Face ID、Windows Hello、通行密钥 **在 Bot 的电脑上都不能用**。做法：

1. 让 Bot 打开公司应用；
2. 到登录页时 Bot 显示 **Computer – Action needed** 卡片；
3. **Take over**，用公司允许的方式登录（密码+验证码、手机推送确认等）；
4. **I'm done**。

Mac 和 Windows 上还可以用 **硬件安全密钥**（如 YubiKey）：**Settings → General → Security Key → Use hardware security keys**，每次使用都会请你确认。

### 命令行工具的登录（如 `gh`）

Bot 可以在云电脑终端里启动 `gh auth login` 之类的登录流程；需要你输入密码、2FA、设备码或在浏览器确认时，会把屏幕交给你。登录状态会保留，之后所有 Bot 都能用。

## 4. 网站屏蔽或连不上怎么办

- 有些网站会屏蔽来自云服务器的流量，或者弹验证码。Bot 会把这一步交给你。
- 网站超时、报安全连接错误、一直加载不出来：这是因为云电脑走 Cursor 的共享网络出口，**Update / Recover / Reset 都解决不了**。
- 解决办法（**Settings → Computer → Your computer**）：
  - **Route traffic through this computer**：让云电脑的浏览器流量走你桌面电脑的网络，网站看到的是你的网络和 IP。只对新连接生效，需要桌面 App 开着。若提示先更新 Bot 电脑，点 **Update**。团队管理员可能锁定此开关。
  - **Execution on this computer**：让 Bot 在你本机执行命令和脚本（包括 API 调用）。见 [第 6 章](06-coding-with-grokbot.md)。

## 5. 给 Bot 下浏览器任务的技巧

- **给出确切的 URL**，尤其是带搜索条件的链接（例如购物站搜索结果页、Google Flights 带日期的链接），比让它从首页一路点过去快得多、也准得多。
- **说清楚结果和停止点**，而不是每一步怎么点。例如："把这三件加入购物车，停在结算页，截图给我，不要下单"。
- **大量结构化数据**（比如要导入 200 行联系人）：让 Bot 先在电脑上生成 CSV 再上传导入，而不是一条条手打。
- **长任务要有耐心**：注册、验证码、长表单可能要几分钟，Bot 一般会先告诉你。
- **要截图作证**：让它在关键节点截图（购物车、确认页、提交后页面）。不要只依赖截图判断快速变化的数据。
- 内置的「站点手册」：Grok Bot 对一些常用网站（如 Target、Best Buy、Costco、eBay、Etsy、Craigslist、Facebook Marketplace、DoorDash、Instacart、OpenTable、Resy、Airbnb、Expedia、Google Flights、United、Southwest、LinkedIn、Luma、Realtor.com、UPS、USPS、FedEx 等）有专门的操作手册，执行这些站点任务时会更顺。

## 6. 安全须知（务必读）

- **所有 Bot 共用一个浏览器会话。** 你在云电脑上登录了 Amazon，理论上任何一个 Bot 都可以像人一样在上面买东西——真正拦住它的是 **审批机制和 Auto-review 规则**（见 [第 10 章](10-security-and-privacy.md)）。
- **不想让任何 Bot 使用的账号，不要在云电脑上登录。**
- 当你和同事的 Team Bot 对话时，它通常也在你的电脑上工作，因此也能用到这些登录。
- 有的网站会让会话过期或重新验证。告诉 Bot"遇到这种情况就暂停并通知我"，不要让它想办法绕过。
- **在输入任何凭据或批准对外操作之前，先确认链接的真实去向。**
- 网页、邮件等外部内容可能含有「诱导指令」（prompt injection）。Grok Bot 会把外部内容标记为不可信数据，并有 Auto-review、审批等多层防护，但风险无法完全消除——这正是重要操作要保留人工审批的原因。
- 项目结束后清理：暂停/删除相关例程、在云电脑上退出网站登录、断开不用的连接器并在源服务撤销授权、删除 `/workspace` 中的敏感文件。**删除 Bot 不会清除电脑上的文件和浏览器会话。**

## 7. 桌面上的其他能力

- 云电脑是一台真正的 Linux 电脑：可以安装软件、运行脚本、处理文件（官方 DevRel 博客里的人甚至在上面装了老游戏来演示——严肃的含义是：这是一台真电脑，交给它真凭据前要想清楚）。
- 生成各类文件：表格、CSV、文档、演示文稿（.pptx）、图片、压缩包等，作为卡片出现在聊天里可预览、保存。
- 演示文稿：Bot 会先问你用 **Google Slides 还是 PowerPoint**（或其他），在大纲和样稿阶段停下来让你确认，最后把成品放到你指定的位置（例如上传到 Google Drive 并转换成原生 Slides）。
- 社区汇总的 0.70.2 更新说明提到：Bot 可以把网页保存为 PDF，并新增「页内查找」。（非官方文档）
