# 02 · 核心概念：Bot、云电脑、桌面、记忆、技能、团队

[← 返回目录](../README.md)

如果你只记住一件事：**Grok Bot = 多个有岗位的 AI 同事 + 一台它们共用的云电脑 + 一套「先问你」的安全机制。**

---

## 1. Bot（机器人 / AI 同事）

Bot 是一个 **长期存在的 AI 同事**：有名字、岗位、自己的对话，以及随时间积累的工作上下文。

### 什么时候该新建一个 Bot？

当一项工作有 **不同的目标、工具、工作风格、审批边界或固定日程** 时，就值得单独一个 Bot。官方举的好岗位例子：Talent Scout（人才搜寻）、Expense Manager（报销管家）、Bug Reproduction（复现 Bug）。反例是「General Helper（万能助手）」——它既不能给 Bot 方向，也让积累的上下文难以复用。

**好的岗位描述是「可操作的」**，例如（官方示例的中文意译）：

```text
负责每周的客户健康度复盘。拉取产品使用数据和客服信号，标记流失或扩张的证据，
为客户成功团队产出一份带链接的观察清单。未经批准，绝不联系客户或修改账户。
```

### 创建 / 修改 / 整理

- **创建**：侧边栏 **+**（`Cmd+N`）→ **Create new Bot**。第一条消息写清岗位、信息源、审批边界，并让它 **记住**。
- **长期规则 vs 一次性任务**：
  - 长期规则："从现在起，任何对外消息都要先经我批准。请记住。"
  - 一次性任务："帮这 12 个客户起草跟进邮件。"
- **改名/头像/标签**：点对话顶部的 Bot 名字打开详情，点名字或头像编辑；或右键侧边栏 → **Rename Bot**。
- **整理**：置顶、分组（Sections，桌面和 iOS 同步）、隐藏。
- **Bot 也会建 Bot**：已有的 Bot 可能会建议或直接创建一个专注某项工作的「助手 Bot（helper Bot）」，它会出现在侧边栏里；不想被它打扰可以关掉它的通知或隐藏它。

### 分享 Bot（模板）

- 通过 Bot 详情的 **Share → Create template → Copy link** 生成 **模板链接**。对方得到的是 **一份副本**（身份、描述、技能、例程等配置），**拿不到你的电脑、登录状态和对话历史**。
- 分享前务必去掉 API Key、内部网址、客户数据——模板会暴露配置内容。
- 你也可以直接在聊天里让 Bot "把你自己导出成一个可分享的模板"，它会逐项检查记忆、技能、例程和插件，去掉人名、密钥、私有链接等再打包。
- 想让整个团队 **共用同一个 Bot** 而不是各自一份副本 → 用 **Team Bot**（见下文第 7 节）。

## 2. 云电脑（Bot's computer / 社区常称 "box"）

这是 Grok Bot 和普通聊天 AI 最大的区别。

- 一台 **持久化的云端 Linux 电脑**，有浏览器、文件系统、终端。
- **你的所有 Bot 共用这一台电脑**：浏览器 Cookie / 登录状态、文件、命令行凭据全部共享；一个 Bot 保存的工作，另一个 Bot 可以接着做。
- 电脑属于 **你的账号**，不属于某个 Bot。所以 **不要把 Bot 当作安全边界**：不想让某个 Bot 用的凭据，就别放到这台电脑上。
- 用户之间是严格隔离的：每个用户一台独立的、硬件隔离的虚拟机（官方安全文档：Firecracker microVM）。
- **合上笔记本、关掉 App、锁屏手机，都不会停止后台任务或例程。** 空闲时电脑会自动休眠（休眠≠删除）。
- 共享工作目录是 `/workspace`。重要文件放在这里的项目文件夹中。
- 云电脑目前运行在美国。

### 什么会保留、什么会丢？

| 内容 | 说明 |
|------|------|
| 对话历史 | 存在电脑之外，电脑出问题也不会丢 |
| 已同步的文件、浏览器登录状态 | 更新 / 恢复 / 重置后都会恢复 |
| 手动安装的软件包（apt / npm / pip、CLI、`node_modules`、Python 虚拟环境等） | 「计算机更新」、Recover、Reset 会清掉，需要重装 |
| 极近期、尚未保存的改动 | Recover / Reset 在电脑无法连上时可能丢失 |

> 社区经验（Reddit）：有人让 Bot 在云电脑上自己设置 cron 定时任务来省用量，结果电脑更新后被清空了。**需要长期定时运行的东西，用官方的「例程」而不是自己装的 cron。**

## 3. 桌面（Desktop / Screen）

- 共享电脑上，**每个 Bot 有自己的一块屏幕**，所以多个 Bot 可以并行使用浏览器和桌面应用；但每块屏幕同一时间只跑一个「电脑操作」任务。
- 屏幕是工作台，不是安全边界。
- **看它干活**：点对话右侧面板里的电脑预览即可打开，实时看点击、输入、页面跳转。离开预览不影响工作。
- **接管（Take over）**：遇到密码、通行密钥（passkey）、两步验证、验证码、支付或身份核验时，Bot 会把电脑交给你。你只完成被卡住的那一步，然后点 **I'm done** 让它继续。详见 [第 5 章](05-browser-and-desktop.md)。
- **你本地的电脑是另一回事**：Bot 只有在你允许时才会在你的 Mac/PC 上执行命令（默认每条命令都要你批准）。见 [第 6 章](06-coding-with-grokbot.md) 与 [第 10 章](10-security-and-privacy.md)。

## 4. 记忆（Memory）

- 每个 Bot 会保留 **稳定的偏好、重要事实和过往工作的摘要**，所以不用每次重讲背景。
- **不同 Bot 的对话和学到的上下文是分开的**；它们通过共享文件、浏览器会话、群聊和直接交接来传递上下文。
- 让它记住某件事，直接说"请记住……"；纠正过时的信息也直接说。
- 记忆不是权威数据源：
  - 经常变化的事实放在源系统里；
  - 重要决定前，让 Bot **重新打开当前数据并引用来源**；
  - 安全边界要靠 **审批和 Auto-review 规则**，不能只靠记忆。
- 一些内置能力也用记忆，例如：你设定的 **月度购物预算**、每次下单后的 **消费记录**，问"这个月花了多少"时它会据此回答（见 [第 9 章](09-shopping-travel-food.md)）。

## 5. 技能（Skills）

技能 = **一套可复用的「怎么做某件事」的说明**：步骤、判断规则、输出格式、安全边界。

- **所有 Bot 共用一个私有技能库**（某个 Bot 可能还需要相应的连接器或登录才能用）。
- **保存技能**：做完一次满意的任务后直接说：
  ```text
  把我们刚才的流程保存成一个叫「每周客户健康度」的技能。包括数据来源、风险定义、输出格式，
  以及「联系客户必须先经我批准」这条规则。
  ```
  Bot 发现某个多步骤任务明显值得复用时，也可能主动保存并告诉你。
- **调用技能**：在输入框输入 `/`，从列表中选择；例程里也可以 @ 提到某个技能。
- **好技能应写明**：何时使用、需要的输入与权限、步骤顺序、如何验证结果、返回什么、哪些步骤需要审批。
- 私有技能不出现在 `/` 菜单里时：打开侧边栏 **Connect apps**，点标题旁的已连接数量，在 **Private skills** 里为当前 Bot 启用。
- **插件自带的技能**（来自已安装的连接器插件）是只读的，通过安装/卸载插件管理。
- 删除技能是全局的（所有 Bot 都会失去它），Bot 删除前会先跟你确认。

### 演示教学（Teach a task）

不想写步骤？**演示一遍** 就行：

1. 在一对一对话中打开电脑视图，选择 **Teach a task**；
2. 描述你想要的结果，然后亲手在云电脑上操作一遍（最长 10 分钟，**不录麦克风**）；
3. Bot 会把录屏整理成一个 **草稿技能**：参数化输入、标出需要确认的关键步骤（下单、发消息、付款）。

注意：**演示时不要输入密码等机密**（用安全表单）；学到的技能是草稿，先补充判断规则和失败处理，再在安全输入上测试，最后才排进例程。该功能正在逐步推出，看不到按钮就改用文字描述 + 一次完成的任务来建技能。

## 6. 例程（Routines）

例程 = **一个保存好的指令 + 一个触发条件**（定时，或 Slack/GitHub/邮件/Webhook 等事件）。它让某个 Bot 在你不在时自动工作。完整说明见 [第 4 章](04-routines.md)。

技能和例程的关系：**技能描述「怎么做」，例程决定「谁在什么时候做」。**

## 7. 多 Bot 协作与「同事」（Teammates）

### 群聊（Group chats）

- **New chat** → 选择 2–6 个 Bot → 说明目标和每一步的负责人。
- 正常发消息让 Bot 们自己决定谁回答；用 `@名字` 指定某个 Bot；`@everyone` 留给全组通知。
- 推荐的开场白是「每个阶段一个负责人」：
  ```text
  @Researcher 收集资料并为每个论点附上链接。@Writer 把结论写成发布稿。
  @Reviewer 对照资料检查稿件，只列出阻塞性问题。不要发布任何东西。
  ```
- 群聊不能语音通话；群聊也没有每个 Bot 单独的通知开关。
- **每条 Bot 回复都消耗用量**，包括群聊里和 Bot 之间的消息。群里 Bot 越少，回复越少。

### Bot 之间交接

- 一个 Bot 可以异步给另一个 Bot 发消息，对方被唤醒处理后再回复；你能在对话里看到交接过程。
- 适合「一个 Bot 管数据源，另一个 Bot 管交付物」，或长任务需要无人值守地往下传。
- 每个阶段只安排 **一个负责人**，并行交接容易重复劳动。
- 不想让它们互相发消息？没有开关，直接告诉它们"不要给其他 Bot 发消息，先问我"，并让每个 Bot 记住。

### Team Bot（团队共享 Bot）

适用于 Cursor 团队成员：

- 命令面板（`Cmd+K` / `Ctrl+K`）→ **Create new Team Bot**；或在已有 Bot 详情里 **Share → Share with your Team** 生成团队副本。
- 拥有者决定谁能用（全队，或指定人和组）；可添加 **Collaborator**（可聊天）或 **Manager**（还能改配置、分享）。
- **每个人与 Team Bot 的对话是私密的**，拥有者和 Manager 也看不到。
- Team Bot 使用 **拥有者添加的应用和密钥**；在你自己的对话里它也可以用你的应用，但会先弹出 **Allow** 卡片征求你同意。
- 回复消耗的是 **被回答者自己的用量**。
- 可以通过 **Bring to your team's Slack → Connect** 接入 Slack，拥有独立的 Slack 应用和 @名称。
- 在你自己的对话里，Team Bot 通常在 **你的** 云电脑上工作（能用你那里的文件和登录）。

## 8. 术语速查

| 英文（App 内） | 本指南用词 | 说明 |
|---------------|-----------|------|
| Bot | Bot / AI 同事 | 有岗位和记忆的长期智能体 |
| Bot's computer | 云电脑（box） | 所有 Bot 共用的云端 Linux 机器 |
| Screen / Desktop | 屏幕 / 桌面 | 每个 Bot 在共享电脑上的独立画面 |
| Connect apps / connector / plugin | 连接器 / 插件 | 与外部服务的结构化集成（基于 MCP） |
| Skill | 技能 | 可复用的做事方法 |
| Routine | 例程 | 定时或事件触发的自动任务 |
| Page | 页面（Pages） | Bot 为你制作并持续更新的文档/看板 |
| Approval / Auto-review | 审批 / 自动审查 | 敏感操作前的确认机制 |
| Take over | 接管 | 你亲自操作 Bot 的电脑完成敏感步骤 |
| Team Bot | 团队 Bot | 团队共享、每人对话私密的 Bot |
| Template | 模板 | 可分享的 Bot 配置副本 |
